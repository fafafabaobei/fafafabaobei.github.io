原生js常见问题
  • 文件太大
    多个文件会导致加载速度慢，而合并成一个文件，会造成网络瓶颈，会有短暂的白屏现象
  • 作用域问题
    在一些库文件，jquery、lodash、bootstrap分别会在window下绑定全局变量(例如$、_ 、还有自己绑定的变量)，会污染window对象变得臃肿
  • 可读性差
  • 可维护性弱
    所有文件都合并在一个超大文件里，可读性差，维护性差

作用域问题解决

早期使用grunt、gulp来管理项目资源(任务执行器)、利用js的立即调用函数表达式(IIFE)，将所有项目文件拼接组合在一起，现在则是以esmodule，comminjs的模块化，但浏览器并不完全支持commonjs，通过webpack对commonjs进行打包

Loader

为什么需要使用loader

前端项目中，需要处理不同类型的文件，例如 JavaScript、CSS、图片、字体等

  • 处理不同类型的文件
    css，sass/less、TypeScript、图片、字体等，es语法转换
  • 模块化
    以模块化的方式组织和管理，根据配置保持项目的一致性
  • 提高开发效率
    构建时自动处理代码、样式、资源的转换工作
  • 解决ES语法的兼容性
    大部分浏览器不兼容太新的es语法

loader是什么

Loader 是 Webpack 中的一个功能，用于转换模块的类型

常用的 loader 包括：

  • babel-loader：用于将 ES6+ 的 JavaScript 代码转换为 ES5，使其能够兼容旧版浏览器。
  • style-loader 和 css-loader：用于处理 CSS 文件，使其能够在 JavaScript 中引入。
  • sass-loader：用于将 SASS（或 SCSS）文件转换为 CSS。
  • file-loader 和 url-loader：用于处理图片和字体等静态资源。
